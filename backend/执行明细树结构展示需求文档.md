# 任务需求文档：执行明细树结构展示

## 1. 背景与目标

### 1.1 背景
当前自动化测试执行明细记录采用平铺结构存储，当脚本包含"引用公共脚本/接口"步骤时，存在以下问题：
- **步骤序号重复**：容器步骤和被引用步骤都使用 `step_no`，导致序号重复
- **顺序不清晰**：无法直观看出执行顺序
- **层次不明**：无法看出哪些步骤属于哪个引用

### 1.2 目标
- 实现执行明细的树结构展示，清晰标识步骤的层次关系
- 保证执行明细记录的查询顺序不会错乱
- 支持前端树结构展示
- 完全对齐 AutoTestStepModel 表的步骤树结构

## 2. 需求描述

### 2.1 功能需求

#### 2.1.1 添加 `step_order` 字段
- **字段名**：`step_order`
- **数据类型**：字符串（VARCHAR）
- **长度**：128
- **描述**：步骤执行顺序，支持小数点表示层次关系
- **示例**：`"1"`, `"2"`, `"3"`, `"3.1"`, `"3.2"`, `"1.1.1"`

#### 2.1.2 添加 `parent_step_id` 字段
- **字段名**：`parent_step_id`
- **数据类型**：BIGINT
- **允许空**：是
- **描述**：父级步骤ID，标识父子关系

#### 2.1.3 修改 `_save_step_detail` 方法
- **功能**：生成 `step_order` 和 `parent_step_id`
- **规则**：
  - 普通步骤：`step_order = str(step_no)`，`parent_step_id = None`
  - 容器步骤（引用公共脚本/接口）：`step_order = str(step_no)`，`parent_step_id = None`
  - 被引用步骤：`step_order = f"{quote_case_id}.{step_no}"`，`parent_step_id = quote_case_id`
  - 循环子步骤：`step_order = f"{parent_step_order}.{step_no}.{loop_cycles}"`，`parent_step_id = 循环容器步骤的step_id`
  - 条件分支子步骤：`step_order = f"{parent_step_order}.{step_no}.{branch_index}"`，`parent_step_id = 条件分支容器步骤的step_id`

#### 2.1.4 修改查询接口
- **功能**：支持树结构查询
- **排序规则**：按 `step_order` 排序
- **返回格式**：树结构

### 2.2 树结构组成策略

#### 2.2.1 AutoTestStepModel 树结构组成策略
- **根步骤**：`parent_step_id = None`
- **子步骤**：`parent_step_id = 父步骤的step_id`
- **引用步骤**：`quote_case_id = 被引用用例的case_id`
- **排序规则**：同一父级下按 `step_no` 排序

#### 2.2.2 执行明细树结构组成策略
- **根步骤**：`parent_step_id = None`
- **子步骤**：`parent_step_id = 父步骤的step_id`
- **引用步骤**：`quote_case_id = 被引用用例的case_id`
- **排序规则**：同一父级下按 `step_order` 排序

#### 2.2.3 字段对齐策略
- **`step_id`**：关联 AutoTestStepModel 的 `step_id`
- **`parent_step_id`**：关联 AutoTestStepModel 的 `parent_step_id`
- **`quote_case_id`**：关联 AutoTestStepModel 的 `quote_case_id`
- **`step_no`**：保留 AutoTestStepModel 的 `step_no`，用于标识步骤在同级中的序号
- **`step_order`**：增强字段，用于标识步骤的执行顺序和层次关系，支持小数点表示嵌套结构

#### 2.2.4 循环结构处理策略
- **循环容器步骤**：`step_order = str(step_no)`，`parent_step_id = None`，`loop_cycles = None`
- **循环子步骤**：`step_order = f"{parent_step_order}.{step_no}.{loop_cycles}"`，`parent_step_id = 循环容器步骤的step_id`，`loop_cycles = 当前循环圈数`
- **循环变量记录**：每次循环的变量值存储在 `loop_variables` 字段中
- **循环状态记录**：每次循环的执行状态存储在 `loop_status` 字段中

#### 2.2.5 条件分支结构处理策略
- **条件分支容器步骤**：`step_order = str(step_no)`，`parent_step_id = None`，`branch_index = None`
- **条件分支子步骤**：`step_order = f"{parent_step_order}.{step_no}.{branch_index}"`，`parent_step_id = 条件分支容器步骤的step_id`，`branch_index = 命中分支的序号`
- **分支条件记录**：分支条件存储在 `branch_items` 字段中
- **分支状态记录**：分支执行状态存储在 `branch_match` 字段中

#### 2.2.6 嵌套结构处理策略
- **循环嵌套条件分支**：`step_order = f"{parent_step_order}.{step_no}.{loop_cycles}.{branch_index}"`
- **条件分支嵌套循环**：`step_order = f"{parent_step_order}.{step_no}.{branch_index}.{loop_cycles}"`
- **循环嵌套循环**：`step_order = f"{parent_step_order}.{step_no}.{loop_cycles}.{inner_loop_cycles}"`
- **条件分支嵌套条件分支**：`step_order = f"{parent_step_order}.{step_no}.{branch_index}.{inner_branch_index}"`

### 2.3 非功能需求

#### 2.3.1 性能要求
- 查询性能：单次查询响应时间不超过 500ms
- 并发性能：支持 100 并发查询

#### 2.3.2 兼容性要求
- 数据库兼容：支持 MySQL 8.0+、Oracle 11g+
- 接口兼容：保持现有接口不变，新增字段不影响现有功能

## 3. 行为定义

### 3.1 正常行为

#### 3.1.1 普通步骤执行
- 生成 `step_order = str(step_no)`
- 生成 `parent_step_id = None`
- 保存明细记录

#### 3.1.2 容器步骤执行（引用公共脚本/接口）
- 生成 `step_order = str(step_no)`
- 生成 `parent_step_id = None`
- 保存明细记录
- 执行被引用用例的步骤

#### 3.1.3 被引用步骤执行
- 生成 `step_order = f"{quote_case_id}.{step_no}"`
- 生成 `parent_step_id = quote_case_id`
- 保存明细记录

#### 3.1.4 循环容器步骤执行
- 生成 `step_order = str(step_no)`
- 生成 `parent_step_id = None`
- 生成 `loop_cycles = None`
- 保存明细记录
- 执行循环子步骤

#### 3.1.5 循环子步骤执行
- 生成 `step_order = f"{parent_step_order}.{step_no}.{loop_cycles}"`
- 生成 `parent_step_id = 循环容器步骤的step_id`
- 生成 `loop_cycles = 当前循环圈数`
- 保存明细记录

#### 3.1.6 条件分支容器步骤执行
- 生成 `step_order = str(step_no)`
- 生成 `parent_step_id = None`
- 生成 `branch_index = None`
- 保存明细记录
- 执行命中分支的子步骤

#### 3.1.7 条件分支子步骤执行
- 生成 `step_order = f"{parent_step_order}.{step_no}.{branch_index}"`
- 生成 `parent_step_id = 条件分支容器步骤的step_id`
- 生成 `branch_index = 命中分支的序号`
- 保存明细记录

### 3.2 异常行为

#### 3.2.1 引用用例不存在
- 记录错误日志
- 容器步骤状态设为失败
- 不执行被引用步骤

#### 3.2.2 被引用步骤执行失败
- 记录错误日志
- 被引用步骤状态设为失败
- 容器步骤状态设为失败

#### 3.2.3 循环执行失败
- 记录错误日志
- 当前循环子步骤状态设为失败
- 根据 `loop_on_error` 策略决定是否继续执行

#### 3.2.4 条件分支执行失败
- 记录错误日志
- 命中分支子步骤状态设为失败
- 条件分支容器步骤状态设为失败

## 4. 边界条件

### 4.1 输入边界

#### 4.1.1 `step_no` 边界
- 最小值：1
- 最大值：999999
- 类型：整数

#### 4.1.2 `quote_case_id` 边界
- 最小值：1
- 最大值：999999999999
- 类型：BIGINT

#### 4.1.3 `loop_cycles` 边界
- 最小值：1
- 最大值：999999
- 类型：整数

#### 4.1.4 `branch_index` 边界
- 最小值：0
- 最大值：999999
- 类型：整数

### 4.2 输出边界

#### 4.2.1 `step_order` 边界
- 最大长度：128
- 格式：`{parent_step_order}.{step_no}.{loop_cycles或branch_index}` 或 `{step_no}`
- 示例：`"1"`, `"2"`, `"3"`, `"3.1"`, `"3.2"`, `"1.1.1"`, `"1.1.1.1"`

#### 4.2.2 `parent_step_id` 边界
- 最小值：1
- 最大值：999999999999
- 类型：BIGINT
- 允许空：是

## 5. 约束条件

### 5.1 技术约束
- 不支持嵌套引用（引用中再引用）
- 不支持循环引用
- 数据库字段长度限制：128 字符

### 5.2 业务约束
- 引用步骤必须是公共脚本/接口类型
- 被引用用例必须存在且状态正常
- 被引用步骤必须属于被引用用例

### 6.2 后端改动策略

#### 6.2.1 修改 `_save_step_detail` 方法
```python
async def _save_step_detail(self, result: StepExecutionResult, step_st_time_str: str, num_cycles: int) -> None:
    """保存步骤执行明细"""
    # 生成 step_order 和 parent_step_id
    step_order, parent_step_id = self._generate_step_order_and_parent_id(num_cycles)
    
    detail_create = AutoTestApiDetailCreate(
        # ... 其他字段
        step_order=step_order,
        parent_step_id=parent_step_id,
        loop_cycles=num_cycles,
        branch_index=self.branch_index,
        # ... 其他字段
    )

def _generate_step_order_and_parent_id(self, num_cycles: int) -> tuple[str, Optional[int]]:
    """生成步骤执行顺序和父级步骤ID"""
    if self.quote_case_id:
        # 引用步骤
        step_order = f"{self.context.executing_quote_case_id}.{self.step_no}"
        parent_step_id = self.context.executing_quote_case_id
    elif hasattr(self.context, 'executing_loop_id') and self.context.executing_loop_id:
        # 循环子步骤
        step_order = f"{self.context.executing_loop_id}.{self.step_no}.{num_cycles}"
        parent_step_id = self.context.executing_loop_id
    elif hasattr(self.context, 'executing_branch_id') and self.context.executing_branch_id:
        # 条件分支子步骤
        step_order = f"{self.context.executing_branch_id}.{self.step_no}.{self.branch_index}"
        parent_step_id = self.context.executing_branch_id
    else:
        # 普通步骤
        step_order = str(self.step_no)
        parent_step_id = None
    
    return step_order, parent_step_id
```

#### 6.2.2 修改查询接口
```python
async def search_step_details(
    detail_in: AutoTestApiDetailSelect = Body(..., description="查询条件"),
    services: AutoTestApiServices = Depends(get_autotest_api_services),
):
    """查询步骤执行明细"""
    try:
        # ... 查询逻辑
        
        # 按 step_order 排序
        order = ["step_order"]
        
        total, instances = await services.detail_curd.select_details(
            search=q,
            page=detail_in.page,
            page_size=detail_in.page_size,
            order=order
        )
        
        # 构建树结构
        tree_data = self._build_tree_structure(instances)
        
        return SuccessResponse(message="查询成功", data=tree_data, total=total)
    except Exception as e:
        # ... 异常处理

def _build_tree_structure(self, instances: List[AutoTestDetailModel]) -> List[Dict[str, Any]]:
    """构建树结构"""
    tree = []
    map = {}
    
    # 建立映射
    for instance in instances:
        map[instance.step_id] = {
            **instance.to_dict(),
            "children": []
        }
    
    # 构建树结构
    for instance in instances:
        if instance.parent_step_id:
            map[instance.parent_step_id]["children"].append(map[instance.step_id])
        else:
            tree.append(map[instance.step_id])
    
    return tree
```
